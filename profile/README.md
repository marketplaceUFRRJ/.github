# Como trabalhamos

Usamos uma **metodologia híbrida**: o lado preditivo cuida de escopo, marcos, riscos e cronograma, e o lado ágil constrói o produto em sprints de 2 semanas. Toda a gestão acontece no **GitHub Projects**, com uma visão do quadro para cada área.

Fluxo de uma demanda: mapear → avaliar e documentar requisitos → priorizar → prototipar → desenvolver → testar e validar → atualizar a documentação → revisar o planejamento → divulgar a entrega.

## Equipe

Somos 26 estudantes, organizados por área:

| Área | Responsabilidade |
|---|---|
| Liderança e PMO | Planejamento, priorização, riscos e acompanhamento do projeto |
| Design | Prototipação e interface (UI/UX) |
| Frontend | Construção das telas |
| Backend | API, regras de negócio e dados |
| QA e Docs | Requisitos, testes, validação e documentação |
| Comercial | Partes interessadas, comunicação e divulgação |

A gestão é compartilhada: oito gestores respondem pelos domínios de desempenho do PMBOK, e cinco deles formam o Núcleo de Liderança Geral (PMO). Decisões operacionais ficam com a equipe de cada área. Mudanças de escopo, prazo ou arquitetura são decididas pelo PMO, por maioria simples (3 dos 5 votos).

## Como contribuir

1. Escolha uma issue no quadro da sua área, no GitHub Projects.
2. Crie uma branch com o padrão `feat/123-descricao`, `fix/123-descricao` ou `docs/123-descricao` (o número é o da issue).
3. Escreva os commits no padrão Conventional Commits, por exemplo `feat: adiciona cadastro de usuario`.
4. Abra um pull request com o mesmo título da issue e `Closes #123` na descrição.
5. Peça revisão a alguém da sua área e aguarde a validação do time de QA e Docs.
